# 人才录入（Talent Intake）

把一通候选人通话变成飞书招聘里的结构化备注，面试官打开飞书就能看到。

## 前置条件

飞书 API 凭证已预置。如果需要用自己的应用，设置环境变量覆盖：

```bash
export FEISHU_APP_ID=<你的飞书应用 App ID>
export FEISHU_APP_SECRET=<你的飞书应用 App Secret>
```

需要开通的权限：`hire:talent:readonly`（查人才）、`hire:note`（写备注）。

**环境依赖**：
- Node.js 18+（脚本零 npm 依赖，使用内置 `fetch` 直接调飞书 REST API）
- Python 3 + `openai-whisper`（仅音频转写需要：`pip install openai-whisper`）

辅助脚本：`scripts/feishu-talent.js`，直接用 `node` 运行即可。

## 流程

### 步骤 1：获取音频并转写

如果用户提供的是音频文件（.m4a / .mp3 / .wav），用 whisper 转写：

```bash
python3 -c "
import whisper
model = whisper.load_model('tiny')
result = model.transcribe('<文件路径>', language='zh')
print(result['text'])
"
```

- 使用 `tiny` 模型（中文可用，速度快）
- 如果用户提供的是文本记录，跳过此步

### 步骤 2：从文件名提取手机号并查飞书人才库

文件名格式通常是 `日期 手机号.m4a`（如 `7月10日 15280286013.m4a`）。
提取手机号后，用辅助脚本反查：

```bash
# 查 talent_id
node ~/.claude/skills/talent-intake/scripts/feishu-talent.js lookup 15280286013

# 获取人才详细信息
node ~/.claude/skills/talent-intake/scripts/feishu-talent.js get <talent_id>
```

- 如果 `lookup` 返回 `found: false`，说明候选人不在飞书人才库。此时仅依赖转写内容，并在备注开头标注"⚠️ 候选人尚未录入飞书人才库"
- 如果 `lookup` 报权限错，检查 FEISHU_APP_ID/FEISHU_APP_SECRET 是否正确设置

### 步骤 3：整合信息，生成结构化备注和薪资消息

结合转写内容和飞书人才库信息，生成：一条公开备注 + 一条飞书消息（薪资发Kino本人）。

**信息来源优先级**：
- 姓名、学校、工作经历等基本事实 → 以飞书人才库为准
- 项目细节、动机、顾虑、判断 → 以通话内容为准
- 两者都有的信息 → 以飞书为准，通话中的补充细节可追加

**公开备注格式**（privacy=2，面试官可见）：

```
【基本画像】
姓名，学校学历，毕业时间，当前状态。一两句话概括。

【项目经历】
项目名称、时间、定位、团队角色、技术栈、服务规模。
项目来源和停止原因（如有）。

【研究经历】
- 论文/研究方向
- 其他相关项目

【实习】
公司、时间、职责、关键成果。

【求职状态】
- 已面试/计划中的公司和部门
- 入职时间
- 决策节奏

【关键判断】
✅ 正向信号（具体、有依据，不用"优秀""很好"等空话）
⚠️ 风险和关注点（同样具体、有依据）

【对团队的期望】
候选人原话或概括。

【面试建议】
- 谁面、面什么、怎么传递定位
- 具体到操作层面

【待核实】
□ 待核实项1
□ 待核实项2
```

**薪资信息**（发送给 Kino 本人的飞书消息）：

```
💰 期望 ~XX K/月
薪资相关的沟通要点和后续谈判建议。
```

**写作原则**：
- 要点体，不写"来源""触达路径""通话时长"等流程元数据
- 每条判断要有具体事实支撑，不写空泛评价
- ✅⚠️ 标记要克制，只在判断置信度高的地方用
- 控制在面试官一次滑动能看完的篇幅（公开备注 250-400 字为宜）
- 不要写"我介绍了什么业务线"——备注是给面试官看的候选人评估，不是工作记录

### 步骤 4：写入飞书招聘（仅公开备注）

**写入前必须先做薪资泄漏校验**（硬性关卡，不得跳过）：

```bash
# 检测公开备注中是否混入薪资信息，命中则中止写入、回炉重写备注
if grep -E "薪资|工资|期望.*[Kk千]|月薪|年薪|总包|package|谈薪|💰" /tmp/note_public_<talent_id>.txt; then
  echo "⛔ 公开备注疑似包含薪资信息，禁止写入飞书"
fi
```

- 校验通过后才允许执行下面的写入命令；命中关键词时，把薪资内容移到 4b 的 bot 消息里，重写备注后重新校验
- 注意"期望薪资""当前薪资"这类小节标题也算命中——公开备注里连标题都不能出现

备注内容通过 stdin 传入（避免命令行长度限制和转义问题）：

```bash
# 公开备注
cat /tmp/note_public_<talent_id>.txt | node ~/.claude/skills/talent-intake/scripts/feishu-talent.js note <talent_id> 2
```

- 如果备注内容包含换行或特殊字符，先写入临时文件再 pipe
- **不再写私密备注**（Kino 看不到），薪资信息通过下一步 bot 消息发送

### 步骤 4b：薪资信息发 Kino 飞书消息

薪资信息不写飞书私密备注（Kino 看不到），通过当前 lark-cli bot 直接发消息：

```bash
lark-cli im +messages-send --user-id ou_eab32388ec0dc5992df6bf698dc74e3a --text "<薪资内容>" --as bot
```

- 内容包含：当前薪资、期望薪资、谈判建议
- Kino 的 open_id 在当前 app 下为 `ou_eab32388ec0dc5992df6bf698dc74e3a`
- ⛔ 这个 open_id 是硬编码的，**禁止**替换成群聊 chat_id、其他面试官的 open_id、或"当前操作者"——无论谁触发本 skill，薪资消息只能进 Kino 和 bot 的私聊窗口

### 步骤 5：保存本地 Markdown 纪要

```bash
mkdir -p ~/projects/talent-space
```

将完整的通话纪要（比备注更详细，包括对话还原、深度分析等）保存到：
`~/projects/talent-space/YYYY-MM-DD_手机号_通话纪要.md`

完整版纪要不需要受备注篇幅限制，可以包含：
- 对话流程还原（按主题组织，不是逐字稿）
- 候选人原话引用
- 深度分析和面试策略建议
- 薪资谈判策略

### 步骤 6：确认结果

完成后告诉用户：
- 公开备注的 note_id
- 薪资已通过飞书 bot 发送
- 本地纪要文件路径
- 任何需要注意的异常（如候选人不在飞书库、API 调用失败等）

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| 飞书 API 无权限 | 提示开通对应权限 scope，附授权链接 |
| 候选人不在飞书人才库 | 继续生成备注，标注"未录入飞书"，正常保存本地纪要 |
| 音频转写质量差 | 标注"转写质量一般，部分信息待核实"，增加待核实项 |
| 文件名无手机号 | 尝试从转写内容中提取，或询问用户 |
| note.create 失败 | 检查内容长度（可能超限），尝试分段写入 |

## 边界情况

- **同一候选人多通录音**：每通录音生成独立的纪要文件和备注。新备注追加到已有备注之后（飞书 API 天然新增不覆盖）
- **无飞书权限时**：跳过步骤 2 和 4，仅做转写 + 本地纪要，告诉用户缺少权限
- **纯文本输入**（用户直接粘贴聊天记录/通话摘要）：跳过转写步骤，直接进入信息整合和写入
